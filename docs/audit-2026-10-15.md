# Audit & Upstream Readiness (2026-10-15)

Reviewed REA-FS base: `514e98f`. Reference `libfprint` clone: `6f9479c3d55f847c1b3769f28ceb99227f9858cf`.

## Summary

The repository provides a working `libfprint-tod` C driver prototype tested on a single Acer Aspire A514-54 (`06cb:00dc`, ROM `6.20` build `154`, module `0190:00a2`) and a structured reverse-engineering workbench. **It is not yet an upstream-mergeable `libfprint` MR nor a universal plug-and-play package for all `06cb:00dc` hardware revisions.**

## Key Hardening & Fixes Implemented

| Issue | Resolution |
| --- | --- |
| Single-touch / 25-frame capture | Multi-touch enrollment (5, later 8 stages) separated by physical finger release; 6-frame aligned burst (~100 ms) |
| Baseline subtracted after saturation | Mode-2 reconstruction subtracts the empty-sensor baseline *before* clipping |
| Unvalidated template deserialization | Versioned template header validating dimensions and finite float values |
| Uninitialized fallback on matcher error | Matcher errors propagate cleanly; `fprintd`-supplied templates used directly |
| Frame-count timeout (600 frames) | Monotonic wall-clock deadline + per-chunk USB timeout clamping ($\le 1\text{ s}$) |
| Worker-thread `libfprint` notifications | Progress, finger status, and completion dispatched on the GMainContext; USB I/O and FFT matching run in the worker |
| Hardcoded paths & real-credential tests | Configurable state directory (`/var/lib/fprint/syna_00dc`); offline tests use synthetic fixtures |
| Immediate system mutation in installer | Dry-run plan by default (`--apply` required), `pkg-config` TOD path lookup, and private rollback manifest |
| Overstated "0% FAR/FRR" claims | Clarified as observed separation (`0.64–0.94` genuine vs. `0.08–0.32` impostor) on local trials, not population metrics |

## Remaining Blockers for Upstream `libfprint`

1. **Native API & Async Runtime (`FpiSsm`):** `libfprint-tod` uses an out-of-tree plugin ABI. Upstream `libfprint` requires an in-tree driver (`drivers/synaptics_wbdi` or `syna_00dc`) where all USB transfers, calibration, enrollment, verification, and cancellation run asynchronously via `FpiSsm` and `FpiUsbTransfer` without blocking `GTask` worker threads.
2. **OEM Table Provenance:** Distinguish host code from sensor configuration tables (`syna_capture_tables.h`) and pairing blobs (`0x06`), document their exact extraction offsets and SHA-256 hashes, and review redistribution acceptability with `libfprint` maintainers.
3. **Reproducible Fresh-Device Bootstrap:** Validate first-time pairing (`0x4f` ownership + `0x50` public material) and baseline calibration on a second physical reader without pre-existing maintainer credentials.
4. **`FpImageDevice` / NBIS vs. Custom Spectral Matcher:** Upstream `libfprint` prefers `FpImageDevice` + NBIS (`mindtct`/`bozorth3`) for image sensors unless a small-area sensor ($144 \times 56\text{ px}$) demonstrably requires a custom matcher (`FpDevice`). Provide a reproducible offline benchmark comparing NBIS against the 2D FFT + SAT matcher on held-out captures.
5. **`umockdev` / Synthetic USB Replay Suite:** Upstream CI requires deterministic, secret-free USB transfer tests covering open, enroll, verify, cancellation, and malformed packet handling.

## Relationship to `synaTudor` and `python-validity`

- **[synaTudor](https://github.com/Popax21/synaTudor):** Loads proprietary Windows `.dll` binaries (`synaFpAdapter104.dll` for `06cb:00be`) in a sandboxed host process via PE relinking and a WDF/WinBio compatibility layer. Our driver is a clean-room native C implementation of the USB/TLS protocol, Mode-2 decoder, and spectral matcher (no Windows DLL execution).
- **[python-validity](https://github.com/uunicorn/python-validity):** Python reference for older Validity/Synaptics match-on-chip sensors (`0090`/`0097`/`009d`/`009a`). Provided structural hints for `RomInfo` and `TLS-PRF`, but does not support `06cb:00dc` or Mode-2 host-side image reconstruction.
